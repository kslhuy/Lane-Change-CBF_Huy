## How to Read the Two Main Heatmaps

The two titles are different because the script creates two different heatmaps from the same RMSE components.

### 1. Hybrid heatmap: raw severity, normalized color

The title:

```matlab
title(sprintf('Hybrid Analysis: Raw-Normalized Color + Raw RMSE Text - %s Attacks by V%d', attack_type, attacker_vehicle_id));
```

becomes:

```text
Hybrid Analysis: Raw-Normalized Color + Raw RMSE Text - Mix_test Attacks by V1
```

because:

- `%s` is replaced by `attack_type`, which is `"Mix_test"`.
- `%d` is replaced by `attacker_vehicle_id`, which is `1`.

To read this figure:

- First, the script computes the raw combined error:

```text
raw_combined_RMSE = distance_RMSE + velocity_RMSE + acceleration_RMSE
```

- The cell color uses this raw combined error divided by the largest raw combined error.
- The cell text shows the raw combined error itself.

So this figure is best for physical attack severity. A larger printed value means a larger combined estimation error.

### 2. Balanced heatmap: equal component importance

The title:

```text
Balanced Component-Normalized Impact Score - Mix_test Attacks by V1
```

belongs to a different figure. To read this figure:

- Distance, velocity, and acceleration are each converted to a `0` to `1` scale first.
- The three normalized values are then averaged.
- The displayed value is therefore a normalized score, not a raw RMSE value.

This figure is best for asking: "Which attack looks most affected when distance, velocity, and acceleration are treated equally?"

In short, the figures answer different questions.

| Figure | Main question | Cell color | Cell text | Physical RMSE magnitude? |
| --- | --- | --- | --- | --- |
| Hybrid Analysis | Which case/vehicle has the largest raw combined estimation error? | Normalized raw combined RMSE | Raw combined RMSE | Yes |
| Balanced Component-Normalized Impact Score | Which case/vehicle looks most affected after giving each component equal normalized weight? | Balanced normalized score | Balanced normalized score | No |

Use the hybrid figure as the main paper figure when you want physical severity. Use the balanced figure only as a supporting comparison when you want each error component to have equal visual weight.

## How RMSE Is Computed

For one observer and one target vehicle, the observer compares its estimated global state with the true state over a selected time window.

For distance:

```text
distance_RMSE = sqrt(mean((estimated_x - true_x)^2))
```

Similarly:

```text
orientation_RMSE = sqrt(mean((estimated_theta - true_theta)^2))
velocity_RMSE    = sqrt(mean((estimated_v - true_v)^2))
acceleration_RMSE = sqrt(mean((estimated_a - true_a)^2))
```

The script computes two windows:

| Window | Meaning |
| --- | --- |
| Full run | Whole simulation time |
| Attack window | Only `10 s` to `15 s` by default |

Most paper figures use the attack-window RMSE, because that isolates the period when the attacker is active.

The script then averages the RMSE values across observer vehicles. In other words, each non-attacker observer estimates all vehicles, and the plotted value for a target vehicle is the average target RMSE across those observers.

## Main Error Metrics

### Distance RMSE

Distance estimation error in meters. Larger values mean the distributed observer estimated vehicle position poorly.

### Orientation RMSE

Heading/orientation error in radians. It is computed and written to Excel, but excluded from the main combined score plots.

### Velocity RMSE

Velocity estimation error in meters per second.

### Acceleration RMSE

Acceleration estimation error in meters per second squared.

### Raw Combined RMSE

The script defines:

```text
raw_combined_RMSE = distance_RMSE + velocity_RMSE + acceleration_RMSE
```

Orientation is excluded:

```text
raw_selected_metrics = [1, 3, 4]; % distance, velocity, acceleration
```

Important: this is a practical composite error index. It sums quantities with different units, so it is best described as "raw combined RMSE" or "combined error index", not as one pure physical unit.

### Raw-Normalized Impact

The script defines:

```text
raw_normalized_impact = raw_combined_RMSE / max(raw_combined_RMSE)
```

This produces values from `0` to `1`. It preserves the same severity ordering as raw combined RMSE:

- The largest raw combined RMSE becomes `1`.
- Smaller raw combined RMSE values become fractions of the maximum.

Use this when you want a bounded color scale but still want the raw-RMSE ordering.

### Balanced Component-Normalized Impact Score

Think of this score as a three-step report card:

1. Convert distance, velocity, and acceleration errors to the same `0` to `1` scale.
2. Give each included component the same importance.
3. Average the three normalized values.

The formula is:

```text
distance_norm = (distance_RMSE - min(distance_RMSE)) / (max(distance_RMSE) - min(distance_RMSE))
velocity_norm = (velocity_RMSE - min(velocity_RMSE)) / (max(velocity_RMSE) - min(velocity_RMSE))
acceleration_norm = (acceleration_RMSE - min(acceleration_RMSE)) / (max(acceleration_RMSE) - min(acceleration_RMSE))
balanced_score = (distance_norm + velocity_norm + acceleration_norm) / 3
```

In the code, orientation has weight `0.0`, so it is excluded:

```matlab
impact_weights = [1/3, 0.0, 1/3, 1/3];
balanced_component_scores = squeeze(sum(normalized_errors_display .* reshape(impact_weights, 1, 4, 1), 2));
```

Interpretation:

- High balanced score: the case/vehicle is high relative to one or more normalized component ranges.
- Low balanced score: the case/vehicle is low relative to those component ranges.
- Important: this is not a physical RMSE magnitude, so do not use it for severity thresholds.

## Why Hybrid and Balanced Scores Can Disagree

They can disagree because they answer different questions.

| Figure | What controls the ranking | Best use |
| --- | --- | --- |
| Hybrid heatmap | Absolute raw combined error: `distance + velocity + acceleration` | Physical attack severity |
| Balanced heatmap | Average of separately normalized distance, velocity, and acceleration errors | Equal-weight component comparison |

Pedagogical example:

| Case pattern | Hybrid interpretation | Balanced interpretation |
| --- | --- | --- |
| Very large distance error, but small velocity and acceleration errors | Can look strongest because the raw sum is large | May look less dominant because only one component is very high |
| Medium or high errors in all three components | May not have the largest raw sum | Can look strong because several normalized components are high |

Therefore, a disagreement is expected, not a bug. For paper claims about strongest attack severity, use raw combined RMSE or the hybrid heatmap. For supporting discussion about component-balanced behavior, use the balanced score.

## Trust and Weight Metrics

### Mean Trust in Attacker

For each non-attacker evaluator vehicle, the script extracts:

```matlab
trust_trace = squeeze(v.trust_log(1, :, attacker_vehicle_id));
```

This is the evaluator's trust in the attacker over time.

### Pre-Attack Trust

Average trust before attack start:

```text
mean trust from beginning to just before 10 s
```

### Attack-Window Trust

Average trust during attack:

```text
mean trust from 10 s to 15 s
```

### Trust Degradation

Defined as:

```text
trust_degradation = pre_attack_trust - attack_window_trust
```

Interpretation:

- Positive value: trust dropped during the attack.
- Near zero: trust did not change much.
- Negative value: trust increased during the attack.

### Detection Rate

The script uses a reporting threshold:

```matlab
trust_threshold_detection = 0.7;
```

Detection happens when trust in the attacker first falls below `0.7` during the attack window.

```text
detection_rate = number of evaluators with detection / number of evaluated vehicles
```

Important: this `0.7` detection threshold is different from the `0.5` trust threshold used by the trust-weight neighbor selection logic.

The two thresholds have different jobs:

| Threshold | Code variable | Used for | Effect on simulation |
| --- | --- | --- | --- |
| `0.5` | `trust_threshold` from `Config.m` | Decide whether a neighbor is trusted enough for consensus weighting | Yes, this affects which vehicles are used by the observer weight logic |
| `0.7` | `trust_threshold_detection` inside `main_mean_attack_plot.m` | Report the first time the attacker looks suspicious in the terminal/Excel metrics | No, this is only an analysis metric |

So `0.7` does not cut communication and does not remove the attacker from the graph. It only answers: "When did the trust score first become suspicious?" The actual trust-weight mechanism uses `0.5` to decide whether a vehicle is trusted.

If you want the reported detection time to mean the same thing as the trust-weight cutoff, change:

```matlab
trust_threshold_detection = 0.7;
```

to:

```matlab
trust_threshold_detection = trust_threshold;
```

Then detection will be reported only when trust falls below `0.5`.

### Mean Detection Time

Average first threshold-crossing time among evaluator vehicles that detected the attacker. If no evaluator crosses the detection threshold, the terminal prints `no threshold crossing`.

### Consensus Weight on Attacker

The script reconstructs the consensus weight assigned to the attacker from current trust scores:

```matlab
weights_now = weight_trust_module.calculate_weights_Trust(evaluator_id, trust_scores_now, "equal");
attacker_weight = weights_now(attacker_vehicle_id + 1);
```

Interpretation:

- High attacker weight means the observer is still using attacker information strongly.
- Low attacker weight means the trust mechanism is suppressing the attacker's influence.
- Zero attacker weight means the attacker is effectively excluded from that evaluator's consensus update at that time.

### Trusted Neighbor Count

Number of neighbors whose trust score is above the trust threshold used by the weight module. In `Config.m`, the threshold is:

```matlab
trust_threshold = 0.5;
```

The weight module also limits trusted neighbors by `kappa`.

## Which Metric To Use

Use this rule:

| Goal | Use this metric/figure |
| --- | --- |
| Report physical attack severity | Raw combined RMSE |
| Use a 0-1 heatmap but preserve raw severity ranking | Raw-normalized impact |
| Show raw values and normalized colors together | Hybrid heatmap |
| Give distance, velocity, and acceleration equal normalized importance | Balanced component score |
| Claim strongest/weakest attack | Average raw combined RMSE by attack case |
| Rank vehicle resilience | Average raw combined RMSE by vehicle |
| Discuss defense response | Trust and consensus-weight figures |

## Common Pitfalls

- Do not compare balanced score values as if they are RMSE values.
- Do not use balanced score for physical severity thresholds.
- Do not forget that orientation RMSE is logged but excluded from raw combined RMSE.
- Do not confuse the `0.5` trust threshold used for trusted-neighbor selection with the `0.7` detection threshold used for reporting detection time.
- If you change the attack case range, update `all_attack_descriptions` so the plot labels still match the cases.

## Recommended Paper Wording

For the hybrid heatmap:

```text
The hybrid heatmap uses color to show raw combined RMSE normalized by the maximum observed raw combined RMSE, while each cell annotation reports the corresponding raw combined RMSE. The raw combined RMSE is computed over the attack window as the sum of distance, velocity, and acceleration RMSE; orientation is excluded from this composite metric.
```

For the balanced score:

```text
The balanced component-normalized score first min-max normalizes distance, velocity, and acceleration errors separately over the displayed vehicle-case matrix, then averages the three normalized components with equal weights. This score is bounded between 0 and 1, but it is not a physical RMSE magnitude.
```

For trust response:

```text
Trust degradation is computed as the mean pre-attack trust in the attacker minus the mean attack-window trust. The consensus-weight metrics report how strongly non-attacker vehicles continue to weight the attacker in the distributed observer during the attack interval.
```
